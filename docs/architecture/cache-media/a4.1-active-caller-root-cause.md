# A4.1 active caller root cause

The pre-correction audit found six separate active-policy failures: every
policy family still used split cache read/source load/cache write control flow.
The A4 store primitive existed but no active `backend/server.py` caller reached
it. The forward correction adds one server adapter that resolves the existing
registry policy, v2 identity, A3 bounds, and existing jittered TTL, then calls
the A4 store with each caller's original async loader and return value.
