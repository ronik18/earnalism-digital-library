# Lane 5: one approved 40-second wallet acceptance attempt

This is source preparation, not installation or acceptance evidence. Historical
600-second policy, native validators, native120 counters and all six recovery
observations remain unchanged. This fresh owner-approved wallet attempt is not
a seventh recovery claim, a purchase, a credit or a repeat of an old attempt.

The default-off policy binds the approved member hash, current authentication
session, one approval/test ID, and the exact released Open Window catalogue UUID,
package and descriptor. It allows one session and at most 40 cumulative wallet
seconds including heartbeat and final settlement. A zero-debit session still
uses the only start. Transfers and a second start are denied. Existing normal
wallet/transaction/ledger/fractional-carry settlement remains transactional.

`paired_audio_acceptance_operator.install()` is a private operation for the
existing protected controller. There is no new route, CLI or client factory.
The controller must supply its existing server/client and the exact qualified
merged commit plus SHA256s for all four `SOURCE_FILES`; deriving expected values
from the live target itself is not qualification. The operator checks the actual
Railway project/environment/service/source and local artifact bytes before
opening a snapshot/majority transaction.

Within that transaction it requires the active ordinary member/auth session,
absence of any retained cap or installation marker, no active/paused session,
no prior attempt, no open conflicting native grants, and the exact released
package evidence. It inserts a unique approval receipt and compare-and-sets the
absent cap and durable installation marker. It never replaces even a disabled,
expired or null cap. The approved member's starts also write a monotonic account
admission fence, preventing snapshot write skew between an uncapped start and
installation. Other members receive no new fence write.

There is one transaction/commit attempt and no automatic mutation retry. Any
commit exception means HOLD: reconcile the already-existing receipt, cap and
marker through the existing controller before deciding the outcome. Do not
reinstall, refresh the expiry, delete a receipt, manufacture consumed seconds or
reset historical limits. There is no retirement or cleanup mutation in this code.

Before any later authorized execution:

1. Qualify the exact merged serving candidate through the existing pipeline.
   No production deployment or cap installation is authorized by this document.
2. Complete any separately authorized free Reader acceptance first and settle its
   session. Report it as free Reader acceptance; it does not prove a paid Reader
   debit. Keep playback quiescent during installation. The account-wide cap
   intentionally denies other metered content while retained.
3. Admit the exact one-time operation through the existing controller using its
   genuine qualified source bindings and current member/auth identity. Stop on
   every mismatch. Never bypass a historical validator or observation barrier.
4. Perform only the explicitly approved single bounded Listener attempt when
   execution is authorized. Stop on failure and preserve evidence; no retry.
5. Keep the cap and one-time receipt through final settlement. Require terminal
   session/lock release and wallet/transaction/ledger/counter agreement before
   proposing any separate retirement. Retain the complete budget/counters,
   installation marker and receipt; do not unset a cap as a cleanup shortcut.

Synthetic tests exercise the policy, settlement, replay, provenance refusals,
rollback and unknown-commit behavior. They do not prove real Mongo concurrency,
effective production installation, media playback or paired acceptance. Lane 5
remains open until those actual gates pass under applicable authorization.
