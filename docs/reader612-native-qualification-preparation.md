exclusive reconciliation, fsync and unknown-outcome rules. It accepts only the
canonical existing operations namespace and its bound owner/device/inode/mode
identity. An uncertain attempt cannot be replayed in another directory. The

Execution defaults false and there is no executable CLI entry point. The fixed

approval resolver. It reuses the existing owner-required environment without
changing settings, but accepts only the separate Backend612 approval-only
workflow. Old frontend/observation runs, dispatcher identity and PR reviews do

history API and the numeric owner/environment IDs, not a local approval file.

The resolver verifies the clean local controller commit/tree, exact workflow
bytes at that GitHub commit, current remote main, first attempt, successful

`APPROVE_BACKEND612 <action> <binding_sha256> <controller_sha> <rollback_operator>`

This is one exact future protected review, not an extra signature ceremony.
