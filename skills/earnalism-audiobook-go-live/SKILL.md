# Earnalism audiobook release

The consolidated [single Colab orchestrator](../../docs/earnalism_orchestrator.md)
uses this workflow's actual voice and acceptance evidence. Resolve **The Earnalism
Voice** by exact base/model revision, trained checkpoint, pinned runtime and
per-language qualification; training/reload evidence alone is not premium narration
acceptance. Use the inference-only adapter with source-bound spoken text, separate
unspoken performance captions and supported controls. Do not repeat fixed training
or evaluation takes for a new title, silently fall back to stock/base audio, or
claim that a branded name qualifies an English/Bengali voice. Retain accepted
healthy recordings and cumulative failed/unknown attempts. A genuinely authorized
qualification audition remains distinct from accepted full-title generation.


For original-voice improvement, keep the capability record separate for each
language/gender profile: cleared data, exact trained checkpoint, observed diction
and performance, supported controls, and remaining limitations. A pending publisher
reply blocks only its unqualified corpus, not already-cleared Rasa/SYSPIN work.
Match prior acceptance by audio/source hashes, not row numbers shared across shards.
When adaptation worsens diction, preserve it as evidence and test the smallest
foundation-anchored correction before adding more updates. Qualify dry speech
before scoring; training/reload success and lower loss do not establish narration
quality. Bind a finite next experiment and reuse the existing controller/counters.

For an isolated Colab voice worker, use the optional pre-Drive driver lookup in
[the runtime contract](../../docs/earnalism_orchestrator.md) before authentication/transfers.
Resolve and hash the actual loaded provider library; never guess a driver path
or expand the worker's credential environment. Preserve the original deadline
and consumed attempts. Driver lookup and positional-table preparation are
prerequisites, not evidence of model training or acceptable speech.

Use the fixed hash-verified bootstrap explicitly in each isolated process before
Torch; automatic `sitecustomize` lookup can select a different file. Retain the
bounded primary receipts in saved notebook output before runtime cleanup, then
verify their bytes. Missing child diagnostics leave the actual cause unknown;
a CPU reproduction cannot diagnose Colab or qualify CUDA.

For the English complete-wheel restoration, install only the exact hashed local
closure and retain `pip check` plus installed-version checks; do not re-resolve
Parler's Git metadata dependency or fetch its unpinned repository. Verify saved
cell scope/clock/rate literals, since a numeric widget alone may be uncommitted.

After the final edit to a notebook admission cell, fetch its saved bytes and run the
[read-only control checker](https://github.com/ronik18/earnalism-digital-library/blob/main/scripts/check_colab_scope.py) locally
against independently observed expected literals. Reject duplicate or nonliteral
bindings even when the last assignment looks correct; appended placeholder blocks
can fail before later values are reached. Recheck after any further edit.

Read the current title checkpoint, applicable AGENTS.md and actual owner scope.
Use the existing campaign journal and cumulative counters. Reuse accepted exact
assets and unchanged evidence; never regenerate healthy audio to satisfy a
diagnostic warning. Preserve source books, covers, recordings and existing work.


For a foundation diagnostic, use the separate environment-qualification operation
in the existing single orchestrator; see [foundation qualification](../../docs/earnalism_foundation_qualification.md).
Bind genuine scope and the original clock, verify the complete local wheel
closure and `pip check`, and retain the final owned venv's interpreter, fixed
provider preload and isolated CUDA evidence. Old English setup requests or
disposable lookup receipts cannot qualify that environment. Preparation, package
readiness and a tiny CUDA probe do not establish full-model fit, voice quality
or release acceptance; qualification does not dispatch the two scenes. Keep
execution disabled unless that exact operation is authorized.

After a restored runtime generates trial audio, verify spoken content separately
from successful model loading and token-limit receipts. A completed take with
`token_cap_reached: false` can still carry fidelity warnings. Retain the exact
audio, captions, fingerprints and raw diagnostics for adjudication; an ASR warning
is not a confirmed listening defect or permission to regenerate. Preserve active
owner holds and consumed attempts until the affected evidence is actually resolved.

Before allocating Colab, verify the target Python ABI in the provider's current
runtime-version documentation and pin a compatible image in notebook metadata.
Retain the actual interpreter preflight before storage or model work.

For voice revision, keep copyright/paired-text qualification separate from a
reference recording's naturalness and expressive suitability. Record a rejected
reference against its actual clip/compilation hash and review scope; do not infer
individual causes, timestamps, accent findings or numerical grades. Preserve its
licence and split history, but do not promote it as an approved performance target
or spend on a claimed repair using that unchanged rejected target.

Check how the backend uses a selected voice reference. The current Parler path
accepts text and unspoken captions; source audio is a comparison target, not an
audio-conditioning input or proof of speaker transfer. Keep the preferred time
window, complete paired recording and unseen evaluation separate. Never attach
a whole-utterance transcript to an incomplete audio crop. Preserve the original
published test partition when a reference is reused; disclose that exposure.

For future owner-authorized voice completion jobs, use completion milestones
and observed progress/credit usage instead of agent-invented trial windows or
transfer-quota approval loops. Reuse verified staged inputs, qualified environments
and healthy checkpoints; respect actual provider limits with supported chunking.
Prepare the full OAuth scope and verify a clean settings cell before allocation.
Stop and preserve checkpoint/diagnostics on completion or error, retaining the
primary failure. Legacy scopes keep their original limits and all consumed or
unknown work. Existing credits are not permission for purchases, new keys or
unrelated work; rights/access and truthful candidate acceptance still apply.

For newly authorized automated release jobs select
`editorial_release_policy: "automated-editorial-2026-11-11"` in the manifest and
the backend QA receipt. Use `scripts/produce_release.py` and
`scripts/release_runtime.py`; their common policy must agree at evaluation and
promotion. See `docs/automated_audiobook_editorial_policy.md` in the repository
for the exact contract. Routine owner review packets and numerical human
listening/confidence scores are not required in this mode. Retain actual human
reviews as evidence, without inventing a YES or reporting unperformed checks PASS.
Legacy jobs and immutable historical receipts retain their original contract.

Require a complete source-bound master, appropriate expressive narration,
consistent voice and grammatical pacing, clean joins, intelligible speech and
content-themed score where licensed. Validate score coverage beyond the opening
unit; use deliberate silence where appropriate. Pilot audio cannot stand in for
full-title content. Keep transcript warnings distinct from confirmed defects.
Preserve recording/voice/model/music rights, source fidelity, storage/checksums,
metadata, secure access, correct charging and actual playback/customer-path checks.
Existing holds—including Bicharak—are not lifted by an editorial-policy choice.

Prepare independent titles in parallel where authorized, with one release writer.
Use one coherent platform update when the current allowlist/contract requires it;
do not create a new controller or deployment per title. Read-along, narration-linked
highlighting and text-linked audio navigation remain retired. Use source-bound
NOT_APPLICABLE for actual nonconsumers; preserve native media/chapter controls.

Read original operation counters before dispatch; cached checkpoints may omit a
later attempted or pending component. Never replay it or promote an obsolete
frontend to clear the journal. Preserve all currently released Reader titles.
A new owner allowance needs supported controller admission, not a counter reset.

Separate an explicitly authorized abort-only initial own-metadata observation
from grant, namespace, release and charging writes. The read-only Sredni mode
still requires current member/source evidence, exact scope, a separately pinned
observer version, private execution authority and the original one-shot journal.
It produces no startup/recovery PASS, grant or available-credit claim. Every
write retains its full readiness checks. Wallet balance and visible history do
not establish the remaining campaign allowance; never start playback from them.

No instruction here grants synthesis, allocation, inference/transfer, storage-key,
deployment or customer-credit authority. Keep hard limits and unknown-outcome
no-replay rules; never reset a consumed budget or overwrite original failures.
Distinguish a tool/platform denial from local workflow conventions. Never evade a
denial; separately authorized offline local preparation is not a claim that a
blocked chat resumed. End with actual local/runtime states and one next action.
