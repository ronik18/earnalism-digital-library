# Earnalism audiobook release

The consolidated [single Colab orchestrator](../../docs/earnalism_orchestrator.md)
uses this workflow's actual voice and acceptance evidence. Resolve **The Earnalism
Voice** by exact base/model revision, trained checkpoint, pinned runtime and
per-language qualification; training/reload evidence alone is not premium narration
acceptance. Use the inference-only adapter with source-bound spoken text, separate
unspoken performance captions and supported controls. Do not repeat fixed training
or evaluation takes for a new title, silently fall back to stock/base audio, or
claim that a branded name qualifies an English/Bengali voice. Retain accepted
healthy recordings and cumulative failed/unknown attempts. A genuinely authorized
qualification audition remains distinct from accepted full-title generation.

Read the current title checkpoint, applicable AGENTS.md and actual owner scope.
Use the existing campaign journal and cumulative counters. Reuse accepted exact
assets and unchanged evidence; never regenerate healthy audio to satisfy a
diagnostic warning. Preserve source books, covers, recordings and existing work.

For newly authorized automated release jobs select
`editorial_release_policy: "automated-editorial-2026-11-11"` in the manifest and
the backend QA receipt. Use `scripts/produce_release.py` and
`scripts/release_runtime.py`; their common policy must agree at evaluation and
promotion. See `docs/automated_audiobook_editorial_policy.md` in the repository
for the exact contract. Routine owner review packets and numerical human
listening/confidence scores are not required in this mode. Retain actual human
reviews as evidence, without inventing a YES or reporting unperformed checks PASS.
Legacy jobs and immutable historical receipts retain their original contract.

Require a complete source-bound master, appropriate expressive narration,
consistent voice and grammatical pacing, clean joins, intelligible speech and
content-themed score where licensed. Validate score coverage beyond the opening
unit; use deliberate silence where appropriate. Pilot audio cannot stand in for
full-title content. Keep transcript warnings distinct from confirmed defects.
Preserve recording/voice/model/music rights, source fidelity, storage/checksums,
metadata, secure access, correct charging and actual playback/customer-path checks.
Existing holds—including Bicharak—are not lifted by an editorial-policy choice.

Prepare independent titles in parallel where authorized, with one release writer.
Use one coherent platform update when the current allowlist/contract requires it;
do not create a new controller or deployment per title. Read-along, narration-linked
highlighting and text-linked audio navigation remain retired. Use source-bound
NOT_APPLICABLE for actual nonconsumers; preserve native media/chapter controls.

Read original operation counters before dispatch; cached checkpoints may omit a
later attempted or pending component. Never replay it or promote an obsolete
frontend to clear the journal. Preserve all currently released Reader titles.
A new owner allowance needs supported controller admission, not a counter reset.

Separate an explicitly authorized abort-only initial own-metadata observation
from grant, namespace, release and charging writes. The read-only Sredni mode
still requires current member/source evidence, exact scope, a separately pinned
observer version, private execution authority and the original one-shot journal.
It produces no startup/recovery PASS, grant or available-credit claim. Every
write retains its full readiness checks. Wallet balance and visible history do
not establish the remaining campaign allowance; never start playback from them.

No instruction here grants synthesis, allocation, inference/transfer, storage-key,
deployment or customer-credit authority. Keep hard limits and unknown-outcome
no-replay rules; never reset a consumed budget or overwrite original failures.
Distinguish a tool/platform denial from local workflow conventions. Never evade a
denial; separately authorized offline local preparation is not a claim that a
blocked chat resumed. End with actual local/runtime states and one next action.
