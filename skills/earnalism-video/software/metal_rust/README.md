# Metal Rust: actual-audio silent body adapter

The finite `science-animation` selector `metal-rust` renders the actual registered
`20-metal-rust` explanation. It uses only the maintained React/Remotion package,
SVG, shared package/browser resolver and canonical transparent full lockup. No
Three.js, new package, private asset, account path, voice generator or standalone
component notebook is bundled. Source/hash/word checks prevent relabelling another
topic. The exact reviewed script stays in the private content workspace;
`contract.json` contains only hashes, numeric word ranges and action anchors.

This is a qualitative ordinary wet-iron illustration, not a corrosion-rate or
molecular simulation. The original garden gate/hinge remains the reference.
Water and oxygen reach bare iron; attached corrosion product forms through the
oxygenated wet-iron route. Salt is optional. Water may meet an intact painted
surface while the underlying iron stays isolated. A scratch precedes rust,
confined by the actual scratch mask. No copper/aluminium rust, external battery,
fixed rate or orange dirt is depicted. The retained balanced neutral-water model
and its carrier-path tests support these constraints; it is not a kinetic solver.

Landscape establishes a wide garden/gate context. Portrait independently fills
its picture height with a tall hinge rather than reducing that wide composition.
Both reserve the complete original alpha watermark and blur halo at the stable
destination-safe top-right calculated from actual dimensions. The picture SVG
clips the entire motion/arrow envelope inside its reserved occupied region.
Heading, qualifier and caption ink is checked against its rendered DOM reading
box. These safeguards require actual finished picture/phone/playback review;
source tests do not establish premium appearance or complete AV acceptance.

## Existing fixed science project input

Use the existing `earnalism.media-project.v1` descriptor and bind every input file
and public asset by SHA256. The canonical dispatcher validates inputs before
runtime setup. It keeps narration, current source and measured-timing handoffs
bound to their actual upstream outputs, and returns the unchanged voice-profile
binding. No renderer synthesizes, processes or renames the selected voice.

The project root contains:

- `assembly-manifest.json`: state `ASSEMBLED_PRIVATE_REQUIRES_REVIEW`, topic ID,
  source root, all source `input_files`, manuscript file descriptor, and exact
  `output_files` hashes for the records below, including `narration.wav`.
- `narration.wav`: actual complete native PCM; no estimated duration or silence
  fixture. The validator reads integer/float RIFF chunks without loading a model.
- `voice-binding.json`: internal identity `TheEarnalismVoice`, language `en`,
  exact source/audio hashes, `no_tempo_or_pitch_change: true`, and descriptors for
  the real trained profile and actual native provenance. Existing
  `earnalism_voice.inspect_profile(..., purpose='production')` must confirm actual
  English acceptance. Provenance must bind the same source/profile/checkpoint,
  full exact source coverage, production purpose and selected audio output.
  A named profile or historic Ryan/AcceptedVoiceB record does not satisfy this.
- `timeline.json`: schema `earnalism.metal-rust.timeline.v1`, exact topic/source
  and audio hashes, actual `duration`, `timing_status: actual_audio_aligned`, and
  method `measured_word_alignment` or `human_verified_audio`. `words` contains
  one current recognized word per interval (`word`, `start`, `end`, seconds).
  Their complete normalized token digest must match the exact private script.
  Six contiguous `scenes` use `scene`, `start`, `end`, `word_start`, `word_end`
  and `marks`. Ranges come from the content contract; boundaries and relative
  action marks equal their current measured word onsets. First scene starts at
  zero; the last ends at the actual body duration. Gaps between spoken words
  remain natural. No equal-span, fractional-scene or 18-second study fallback.
- `timeline.json` also binds the current shared score `timing` file and actual
  `word_alignment` file. The latter contains source/audio hashes, real method
  and the same complete actual word intervals. The former uses the existing
  `earnalism.audiobook_score.timing.v1` schema and accepted measured boundaries.
  `captions` carry verbatim text, full ordered word ranges and actual word start/
  end boundaries; unspoken editorial study captions cannot become subtitles.
- `asr-review.json`: actual source validation, differences and the bound word
  alignment hash. `caption-quality.json`: current timeline hash and actual
  issues. Existing unresolved findings remain holds; this adapter invents no
  review or acceptance record.
- `units.json`: current topic/source identity. Generation/attempt histories stay
  in their existing native provenance and are never reset by this module.

`props.json`, `shorts-props.json` and `clean-shorts-props.json` repeat the exact
topic/source/audio identity, real method/status, duration, words, scenes and
captions. `burnCaptions` is true only for `shorts-props.json`. The existing shared
science admission expects `outro: true` as the intended complete-film contract,
then writes isolated body props with `outro: false`. The Rust renderer rejects a
true outro: it produces **silent body only**. The common compositor consumes the
selected dynamically scored master and appends the bound approved three-second
END once with its own sound unchanged. This adapter neither scores nor appends
audio/END, and cannot qualify the missing branded voice or release evidence.

## Source checks

```text
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=skills/earnalism-video/software:. python3 -m unittest metal_rust.test_inputs metal_rust.test_model scripts.test_earnalism_metal_rust_adapter
node --test skills/earnalism-video/software/metal_rust/test_layout.mjs
```

Tests use labelled synthetic in-memory data with the test token digest patched;
they do not generate or qualify a voice or real alignment. Production validators
reject fixture methods and require the real source/token/audio/profile bindings.
Missing actual words, profile qualification, score, full visual/AV review and
final candidate decision remain explicit gaps. No runtime allocation, purchase,
model call, upload or publication authority is created by this source adapter.
