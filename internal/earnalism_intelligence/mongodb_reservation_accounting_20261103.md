# MongoDB reservation accounting: source-only and unwired

This local accounting library is not connected to a Mongo client, process launcher, managed-client grant, scaling provider or production initializer. Importing it creates no ledger. New initialization requires an explicit `offline=True` call and a private owned path. Closing a reservation uses a disabled-by-default trusted verifier; missing or invalid closure and reconnect-fence proof retains the charge.

Each reservation binds target, source, budget, provider revision, generation, cohort, physical-client identity and strict per-node units. Transactions serialize quota checks and inserts across local connections; duplicate identical intents charge once and changed bindings fail closed. UNKNOWN, PENDING, drain, cancellation, expiry and restart do not free capacity. Confirmed closure leaves a tombstone that cannot reopen the same client instance.

The independently found v1 race validated mutable input before detachment. V2 freezes the request and revalidates that exact snapshot before its transaction. Tests cover a real mutator thread, detached-request immutability, concurrent reservations, source/revision/generation mismatch, missing/corrupt ledgers, disabled closure, fake typed proof and process crashes. A child commits UNKNOWN then exits with `os._exit(7)`; reopening retains its charge. Another child exits with an uncommitted DELETE and rollback preserves its charge. These are disposable local unit tests, not load or production capacity evidence.

Run `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v scripts.test_mongo_reservation_accounting`. All 18 cases are included in the mandatory resource CI group. Python 3.11 and 3.12 results and independent review bind frozen source SHA256 `4c5cd3a64e7997c67b0ca61b63c50ce03e6d8714caf737cc07862118d9288cdd`; review SHA256 `253639fc58b98aa94d02a484385ed45f514269e52d4626c4c91f22c27d48edd4`. Original v1 HOLD, failing race and corrected successor history are retained in the private evidence packet.

The local database is a trusted accounting store, not a security or distributed-custody authority. Checksums detect accidental corruption, not hostile privileged edits or signatures. Restoring an older valid ledger of the same generation can lose reservations; global monotonic restore fencing and off-device custody are not supplied here. Snapshot output explicitly says `accounting_only=True` and `custody_verified=False`. Local persistence cannot discover dormant credential holders, prevent out-of-repository clients or establish provider CAS/recovery.

External allowance E, approved reserve R, actual worker/client/rollout bounds, native Redis memory and exclusive controller custody remain unqualified. No deployment, settings, credentials, real quota reservation, customer ledger mutation, paid session or US activation is authorized or performed by this source adoption. Existing disabled authorities and audiobook work remain untouched.
