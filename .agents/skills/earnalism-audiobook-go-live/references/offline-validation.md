# Focused offline validation

Use for a skill audit, simulation or runbook test. Save results privately outside canonical state; never create production evidence or change a title's release flags to make a scenario pass. Inspect commands before executing them: a check/dry-run name does not prove no downloads, allocation, credentials, writes or provider calls.

Use a few realistic decisions and counterexamples rather than a second end-to-end release. Give an independent evaluator only the candidate skill, permitted artifacts and scenario facts, without the author's intended answer. Label observed local checks, dependency-bound reuse, unperformed actions and actual holds separately.

Cover the changed decisions:
- A retained complete accepted mix resumes at its actual source/runtime gate without regeneration, duplicate full dry listening or repeated owner approval.
- A separately authorized nonrestarting policy-only correction can advance while backend recovery is held, but cannot waive its own exact guard/write constraints or authorize backend dispatch.
- One eligible title progresses while another lacks fidelity/sync. One canonical writer and shared resource/credit counters remain protected.
- A skipped local Mongo test or pre-test CI fetch failure does not become hosted CI PASS; diagnose infrastructure without weakening the exact source pin or replaying generation.
- A temporary storage key or member grant is created only when its immediate dependent operation is ready, not while unrelated preparation/CI waits.
- A known failed public read is distinct from an uncertain paid/provider write. A parent technical limit is binding but is not misquoted as owner authority; no silent renewal/reset.
- Raw recognizer output, token-grid geometry, scoped owner adjudication, full scored ratings and accepted measured sync remain different evidence. No best-of-ASR merge, global aliases or estimated cues.
- A changed lease/player/accounting path reopens affected genuine acceptance even when audio bytes are unchanged. No-paid-session still forbids clicking authorization.

Check actual helper behavior only if it changed or the scenario depends on it. The historical roster/old title fixture is a locator; current canonical bindings win. No installed model or paid runtime is needed for a rights-only or textual scenario.

Validate skill structure, links and changed scripts. For this prose change, a small decision record and relevant existing helper tests are enough; word/heading assertions are not behavioral proof. A simulated title is never LIVE. End with actual findings and one next integration action; no approval question is needed for offline validation itself.

Changed-policy counterexamples: a verified standalone nonconsumer retains explicit
NOT_APPLICABLE through evaluation and promotion; bare N/A, changed source, enabled
read-along/highlighting/text navigation and stale candidate binding fail closed.
Warning-only findings do not invent a repair/review gate; confirmed material defects
and absent fidelity/rights/playback/accounting acceptance still block. Reusing an
accepted exact-source report does not rewrite the raw recognizer output or scores.
