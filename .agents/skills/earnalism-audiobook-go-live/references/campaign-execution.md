# One campaign record, action-scoped execution

Use for multi-title work, recovery or a stopped release. This reference owns the gate/dependency model. The runbook supplies execution details; it is not a second plan or approval system. Resolve current identifiers, policy, rights, limits and provider capabilities from actual records.

## One matrix, one journal

Use the existing title/campaign checkpoint as the gate matrix. Each row needs only status, exact evidence references, the dependencies that make it applicable, and the next action. Preserve independent statuses for source QA, listening, storage, source CI, serving, accounting and publication; never compress them into one favorable label.

| Gate / action | Decisive prerequisites and proof | Reopen only the affected dependency |
|---|---|---|
| Source, rights and casting | Complete authoritative edition/order; separate commercial audio/model/exact voice/score rights, consent/use/territory; applicable narrator evidence | Text, identity, licence or intended use changes |
| Production and full scored QA | Approved remaining execution scope if generation is needed; exact spoken-form map; all content/fidelity/fatal/per-dimension/confidence gates; measured text sync where consumed, otherwise verified NOT_APPLICABLE with features/claims off; genuine owner review of the complete final scored mix | Changed words, narration, joins, timing, score or a material new finding |

| Source integration and merge, when changes are required | Supported manager/profile/rights and composed HTTP/client contract; coherent derived bindings; applicable exact-head checks/reviews and reviewed/merged equality for changed source. Reuse compatible qualified serving source when no relevant change is needed | Relevant code, metadata or contracts change |
| Read-only guard comparison / policy-only correction | Its genuine scoped permission, required clean merged source, authorized current data/profile, exact old/proposed bytes, fresh unchanged full-guard result and exclusive configuration writer; one skip-deploy write/readback when approved | Those exact inputs or the action's required freshness change |
| Backend dispatch | Actual source/frontend prerequisites, fresh installed-policy/startup/data/config evidence and compatible recovery required by the current adapter/authority; durable dispatch intent | Deployment, effective policy/config/data/start path or recovery compatibility changes |

| Public release | All applicable preceding release gates, exact tested selection/promotion, actual discovery/Book/Listener/covers/access and applicable genuine playback/accounting; no unresolved material defect | Public selection/access or an actual upstream dependency changes |

This is a dependency graph, not a requirement to finish every row before any work. A deployment recovery HOLD does **not** automatically block an independently authorized, nonrestarting guard comparison or policy-only skip-deploy correction. Check the actual owner scope, setter and platform contract; do not import the backend-dispatch recovery gate into that earlier action. The correction does not qualify a future boot or remove the later installed-policy and recovery gates. Likewise, source CI waiting does not require refreshing a time-limited member grant, and a storage upload need not wait for unrelated future player acceptance. An explicitly authorized read-only member inventory may be useful before serving qualification; it remains raw/proposed observation, not an allowance, grant or runtime PASS.

Keep one cumulative intent journal per authorized operation scope, shared across titles only when the authority actually shares it. Reuse existing provider/release/credit journals; do not replace their schemas or initialize a second allowance. Minimum entry: operation identity/action, authority and limit provenance, exact inputs, dependency evidence, reservation/consumed counters and original clock, intent, actual result or unknown status, and next action. Reference immutable receipts rather than copying them into new approval envelopes. Missing/lost history means reconcile or HOLD, not reseed; use an existing durable outer anchor when output loss could permit replay.

A new score reopens mix review, not healthy narration generation. An ID3-only remux with actual packet/decoded-PCM identity can retain applicable listening proof while updating container/hash/metadata bindings. A changed lease path reopens runtime/accounting, not unchanged literary rights or audio. Evidence reuse needs an actual dependency reason, not a new report for each reference. Old failed attempts remain history after an exact correction qualifies.

## Authority is scoped; limits have provenance

Separate:
- **Owner authority:** the real request/reply and its purpose, spend/access/transfer/attempt limits.
- **Parent-task technical guard:** binding for the delegated task until the authorized parent selects a preserved successor; it is not automatically a human prohibition.
- **Platform/repository requirement:** the current supported adapter, rights, security or release constraint.
- **Implementation preference:** a local conservative choice; it may be corrected with evidence inside higher-level scope, not silently treated as a new permission requirement.

Do not silently renew or reset any of them. A new script, cache, output path, source pin or model name cannot reopen consumed time, requests, takes or grants. An additive allowance retains prior consumption. A technical resource limit may be reconsidered only by its actual authority with carried history; preserve the original admission and precise no-model/pre-write evidence.

Finish free job/import/adapter checks before asking once for missing external scope. A production envelope identifies editions, voice/provider, permitted transfer, per-title and aggregate costs, allocation/time/concurrency/take bounds, pilot-to-remainder conditions, allowed setup repair and shutdown. Voice preference or a quality target does not grant inference or new private access. No synthesis/allocation/no-retry instructions prevail over generic production intent. Use an approved nonsecret authentication-metadata check, where available, before consuming scarce environment-injection/snapshot phases; never inspect tokens or assume a probe is nonmutating from its name.

Distinguish failures:
- Known failed public read: finite supported HTTPS official/CDN transport recovery can continue within the same cleared candidate and actual byte/request scope. One candidate is not one GET unless specified. Reconcile pending native Save dialogs and existing local output before downloading again.
- Proven pre-model/pre-write setup failure: preserve the invocation and counters; validate the narrow correction, remaining deadline and permitted continuation. Do not demand a new owner decision merely because a technical guard came from a parent. Do not execute beyond it without the appropriate selection.
- Failed/uncertain synthesis, paid inference or provider write: count the attempt, retain all outputs and usage, reconcile read-only/status-only, and never automatically replay.
- Approval-review rejection or genuine missing authority: preserve its reason, finish unaffected work and request only the missing scope. Another UI/API/child is not a workaround.

A timed-out or suppressed observation is not proof that remote access never began. Record capture stages and completion separately; keep unknown database progress unknown. Diagnostic code repair and offline tests do not recover a missing runtime projection or authorize another capture. Reuse a retained projection only if its actual identity, inputs and required freshness still qualify. A remaining numeric slot is not retry permission, and an expired original window is not renewed by a new process, source revision or repaired diagnostic. Reconcile existing evidence without replay; if none qualifies, retain HOLD and identify the exact fresh-capture scope needed.

Reserve/fsync intent before the consequential call or counted environment injection. Persist raw returned transcript, done event, response/session identity, usage and audio **before** semantic checks. Publish result files atomically without overwriting a prior final file, so concurrent readers cannot see a partial result. If validation then fails, keep the authentic response and original blocked status; a retained-audio adoption is a distinct evidence-bound decision, not a retry or fabricated transcript.

## Execute, do not keep rediscovering

One Integration Lane owns canonical edits and release state under current AGENTS.md. Parallel eligible titles may progress through independent preparation or already-authorized work; coordinate shared browser/model/CPU/memory resources and never consume another title's allowance. Do not spawn competing canonical writers, branches or release worktrees.

Use three operational stages: qualify the exact scored package, stage it privately, then publish and verify. The matrix above explains their real dependencies; it is not eight mandatory work projects for every title. Use the installed content-publication route when its current source, access and delivery contracts support the package. Source changes, CI, startup correction and deployment/recovery are conditional work, required when the selected package or changed serving implementation actually needs them. Existing unmet runtime requirements remain blocking; calling a release content-only cannot bypass them.

Attach each blocker and proof to the artifact, phase and operation they actually cover. A failed latest attempt is not the serving deployment; a serving-component proof is not qualification of its replacement or the complete Reader/Listener pair. Apply account, admin-access and recovery prerequisites only to operations that need them. Reuse unchanged applicable evidence without another approval, while genuine owner caps, enforced checks and unresolved defects remain binding.

When changing or rebinding operational source, or correcting a demonstrated interface mismatch, trace the existing preflight → capture → dispatch → reconcile → post-acceptance path. Rehearse affected real producer/consumer interfaces offline with synthetic transports, including denied, partial and unknown outcomes. Retain a secret-free failure stage and whether remote access or mutation began; unknown remains unknown. Batch demonstrated cross-phase corrections into one coherent reviewed change set. Finish the changed path’s post-write observer before taking fresh evidence; do not discover its missing bindings after the write. This is source validation, never actual runtime or release PASS. Reuse an unchanged qualified path; an ordinary supported content release needs no new harness or review project.

Use the smallest next action that resolves a real gate. Inspect retained assets before generation, existing adapters before new wrappers and actual source contracts before extra approval machinery. After a bounded diagnostic proves a capability missing, record the precise HOLD and advance another ready action. Do not add another recognizer/calibration/research phase without a decision-relevant question and actual scope. Full scored listening may assess narration and music together; request only unresolved wording/dimensions rather than repeating a complete accepted review.

Prepare and test the real job, adapter and runtime before short-lived storage keys; create them only for immediately executable work. Preserve account/bucket/prefix/TTL/least privilege, key-count uncertainty and all previous counters. Native storage requests/downloads and customer playback credit may be distinct approved scopes; label each honestly without moving an inclusive cap. Reuse actual byte/retention readbacks; do not spend another full-master GET solely to duplicate unchanged proof.
