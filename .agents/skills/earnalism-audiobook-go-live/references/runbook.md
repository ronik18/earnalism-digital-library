Start from the single matrix/journal in [campaign execution](campaign-execution.md). Resolve current source and owner scope; this runbook adds execution detail, not a second stage checklist. Use the existing release manager, adapters and title profile. Add a small reviewed seam only for a demonstrated unsupported boundary.

## Preserve the accepted edition

Inspect retained masters, rights and completed attempts first. Bind the exact authoritative text/order, spoken-form map, voice/provider/model/revision, selected units and accepted final scored mix. Read the whole work before new direction. Use [narrative performance](narrative-performance.md) and [voice engineering](voice-engineering.md) only for relevant media work; the historical roster is not a complete current inventory.

Validate the actual translated worker job and compatible imports without inference before paid setup: model/cache/revision/tokenizer, output paths, supported settings, unit/take/cost limits and original deadlines. No model download, cloud allocation or synthesis to make an offline validator pass. A rights-only decision does not need an installed model.

A pilot is evidence for its actual approved continuation, never full-book acceptance. Keep every attempted result and raw transcript/done/usage before post-generation checks. Use only unattempted authorized units or separately accepted retained repairs; no automatic retry. Freeze source-offset verbalizations for numerals, currency, abbreviations and typography before spending a strict transcript-checked take. Do not alter the Reader or broaden ASR aliases.

Use one complete final scored review for narration and music where it covers both. Keep dry stems and targeted diagnostics. Reuse unchanged genuine owner findings; a new material defect reopens only the affected review. Re-encode/remix changes require affected audio/timing/navigation/hash proof; an ID3-only successor can reuse actual whole-PCM/packet identity evidence.

## Storage ready before expiring credentials

Resolve existing approved profiles/loaders. Browser sign-in is not native upload/retention authority; a role label is not least-privilege proof. Test the actual adapter/finalization path offline with synthetic clients, including required fields in finalized manifests. Qualify payload, descriptor, source prerequisites, carried counters, request/metadata/manifest headroom and actual runtime imports before keys/grants start.

Create temporary roles only under actual count/prefix/capability/TTL authority when upload can begin. Never replace an uncertain key-create or discard a successful opaque secret because of an invented alphabet. Keep all credentials private. Reserve cumulative intent/cost, use supported serialized writes, exact versions, full-byte readbacks, independent DR and approved retention/lifecycle semantics. A Governance no-delete floor does not schedule deletion; indefinite storage and finite protection are different. Do not inherit another title's numeric cap or assume remaining download can fit a full master.

A proven import/pre-client failure differs from an uncertain remote write; preserve its invocation and establish actual no-I/O before a scoped continuation. Do not reseed counters after output loss. Reuse unchanged verified storage receipts; operator readback and customer player verification remain distinct.

Use the supported manager's prepare/qualify/stage/promotion functions and current title profile. Private stage and public promotion are distinct states; storage success or source QA cannot expose the title. Do not fabricate a whole-MP3 URL for protected chunked delivery.

Keep rights/component bindings, both mirrors, registry/bootstrap, cache semantics, runtime inventory, SEO generator **and verifier**, exact fixtures and compiled frontend allowlist coherent. Do not change a pinned expected hash without the intended semantic comparison. Run impacted checks once after a coherent correction. Required transactional financial tests must use the actual supported isolated Mongo fixture in its existing hosted job; local opt-in skips mean unperformed, not PASS. Actual required CI/review is additional to meaningful local verification.

## Close exact-head CI, including infrastructure failures

Determine applicable jobs from current path filters, branch requirements and release policy. Record the exact head/tree and actual outcomes in the existing journal. If required final published review was not scheduled, invoke its supported exact-head entry point once. Do not create an empty commit to trigger a check or reuse an old-head PASS.

Classify a failed job before acting: source/test failure, admission/filter mismatch or infrastructure/read-only setup failure. A Git fetch timeout before tests is not a failed test or a passed source gate. Inspect retained logs, repair the demonstrated transport/deadline boundary or use a supported bounded read-only CI retry within actual authority; keep source pins, assertions and required tests intact. Do not waive a job, blindly extend all timeouts, rerun paid generation embedded in a job or repeatedly rerun a proven configuration. Batch known fixture/derived-contract corrections into one successor.

After all applicable exact-head checks and required published reviews pass, merge the reviewed head through the supported protected path. Fetch main, verify reviewed/merged tree equality and return the clean canonical handoff. One writer/PR does not mean one deployment forever: a meaningful later public-selection or corrective source change may need its own gated changed-service deployment within authority.

## Deploy only the action that is ready

Verify repository deployment controls and provider autodeploy controls separately. Use existing authentication without secret inspection. Change settings only inside actual settings authority. A frontend candidate uses exact Git source with automatic production-domain assignment off; no local dirty-worktree upload. A supported backend artifact must be exported from exact reviewed committed blobs, input-sealed and checked through the established runtime-source path; this is not a generic artifact exception.

Preserve intent/result per changed service. Stage READY is metadata evidence, not HTTP/UI/promotion. Qualify the actual candidate through supported provider access with expected application responses, then promote the tested candidate and verify actual aliases. A timeout or ambiguous write is read-only reconciliation, never another dispatch.

Before **backend dispatch**, bind actual source/frontend prerequisites, effective startup/config/data guard, required fresh installed-policy proof and compatible recovery. An old canRollback flag or CLOSED image may be incompatible with a new policy/data/config. Do not disable the guard, lifespan or auth to get healthy status. A new backend needs actual new serving identity, expected committed runtime inventory/file count, health/DB and normal startup evidence. Preserve a null provider Git SHA and state the limits of runtime-file measurement rather than fill it from a label. Do not redeploy solely for a diagnostic fingerprint.

A separately approved **policy-only skip-deploy correction** uses its own admission: authorized current/profile/data reads, exact old bytes preserved from the same permitted read, proposed bytes, unchanged full-guard PASS, exclusive writer and immediate old-hash comparison/readback. Apply only the approved target/field. This is not provider-atomic CAS unless the provider supplies it. Compatible deployment recovery gates the later backend action; do not add it before this nonrestarting correction unless the actual setter/owner/platform contract requires it. Do not widen read counts/purposes, auto-rollback an unknown write or infer a future boot PASS.

Reuse an unchanged qualified frontend for a backend-only successor when actual contract dependencies still apply. If frontend source changes, make the needed new exact-source candidate. Healthy old service is not successful new deployment.

Use genuine normal-API member/current-session binding and the current supported operator; never manufacture an expected SID from the same DB observation. Preserve stable-account versus immutable full-session binding, ONE-total-grant/history constraints and original owner/counter identity. A fresh login does not reset a closed/unknown grant.

Keep actual original allowance and both metered-microsecond and posted-whole-debit constraints, fractional carry, expiry/revocation/transfer/idempotency and terminal settlement. Use the canonical source-proven BSON precision method, not broad epsilon or manual wallet/ledger repair. Unknown history/remaining remains unknown. Synthetic transactional tests are not actual customer playback.

Under no-paid-session scope, do not click Authorize Listening or start a lease. Check public metadata, covers, entry, guest/expired denials and reuse applicable genuine protected evidence only when unchanged dependencies justify it. If new paid acceptance is indispensable, finish independent work and ask once for that exact scope. When authorized, use the minimum bounded normal-player session, pause/end on error and verify terminal settlement; no unattended billing or assumed test credit.

For changed financial paths, cover applicable concurrency/transfer/stale-owner/account-switch behavior, pause/buffering/seek/source transitions, playback speed and exact owner-scoped usage pagination. Label isolated Mongo, actual browser and physical-device observations separately. A finite matrix is not universal fraud prevention; unsupported cases are explicit limitations.

Declare LIVE only after applicable quality/rights/delivery/source/runtime gates, both production aliases, actual discovery/Book/Listener/covers/access and genuine applicable playback/accounting evidence. Keep reader-only/audio-hidden state intact otherwise. Update required learning/history views from the one operation record; report one blocker/next action rather than another plan copy.
