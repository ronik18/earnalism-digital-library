# Selfish Giant release lessons

Apply only the relevant lessons to the current title. This is a historical evidence locator and decision guide, not permission to run providers or a requirement to replay this release.

## Production and recovery

- Resolve the actual interpreter, Linux architecture/glibc, full hash-pinned wheel closure, system dependencies including sox, imports and real worker job/cache/snapshot contract before allocation. Offline fixtures establish structure, not real GPU/model compatibility. At an authorized runtime, admit actual platform and all planned wheels before downloads; stop on incompatible admission.
- Verify the uploaded notebook’s actual cells against prepared source and the prior-recording preservation receipt before Connect. Bind the original allocation-request clock before execution; no placeholder clock/receipt or assumed UI edit success. For Monaco changes, a clean cell and exact full-source readback avoids accidental prepending.
- Load the model once in a separate persistent worker. Each foreground cell authorizes one selected unit, waits within the original deadline, exports its completed output and returns. Verify durable external copies with full bytes/hash (and fsync where supported), then submit the actual receipt-bound ACK before authorizing the next unit. An archive in output or a browser Save action alone is not durable retention. Offline-test source admission, selected-ID/attempt limits, ACK timeout, recovery and shutdown before another run.
- Save failure is a retention problem, not permission to rerun synthesis. Preserve available output locally, recover the exact completed-cell notebook/archive and compare recording hashes. Do not Save and Reload an active run until its outputs and recovery/worker behavior are understood. Continue only verified unattempted units on the original clock within remaining authority. Verify shutdown/absence; elapsed-rate estimates are not exact CU debit.
- Preserve accepted healthy recordings across allocations; never blindly replay the audition or full book. Build one ordered multi-run manifest proving exact word coverage and original hashes, then losslessly assemble groups/master and qualify wording, joins, samples/timing and completeness. Two ASR models can flag uncertainty but cannot establish subjective age/grief/sincerity. Ask only a specific unresolved material wording/tone question; retain the owner’s actual answer once. Do not invent listening scores or require full manual listening without a policy/material reason.

## Rights and storage

- Reuse accepted source, covers, stock narrator identity and model/runtime licence evidence within exact scope. Tone direction within that identity does not automatically need another identity approval.
- Accepted lifetime India audio_stream authority uses the supported explicit revocable/hash-bound lifetime decision. Do not manufacture an expiration or turn a missing date field into repeated unchanged rights approval. Reader/cover rights remain separate; publication metadata changes can require deterministic component rebinding even when text and image bytes are unchanged.
- A missing local adapter profile is not proof no approved access exists. Inspect existing approved context without exposing values; browser login is not a native/S3 scoped role. Recover account/bucket/topology evidence in its proper scope, verify current independent DR identity/roles and provider retention privately, and ask only for the genuinely unavailable capability. New keys/rotation/settings are separate authorized operations, never automatic prerequisites.
- Reuse exact final primary/DR object and manifest receipts, including versions/full bytes/retention. A stale aggregate status file must not overrule newer actual receipts. Preserve the accepted retention baseline and no-automatic-deletion policy; lifetime availability does not mean Governance protection never expires or storage has no ongoing cost.

## Release contract and authority

Follow [public availability acceptance](public-availability.md) before the first release attempt. The Selfish Giant exposed two distinct defects: legacy approved database fields overwrote canonical protected audio in detail lookup; then a compiled frontend title allowlist omitted the accepted package. Neither was repaired by more narration, uploads, paid playback or weakening guards. Batch applicable lookup/merge/HTTP, client allowlist/enrichment, derived SEO, rights binding and cache-contract changes before exact-head CI/review. Preserve healthy services and deploy only the changed service through the sole owner.

Use native provider source provenance where available. If absent, use the reviewed measured-runtime/exact-Git comparison in [the runbook](runbook.md#verify-actual-serving-source); never claim a local upload seal is running-source proof. Candidate readiness, project/branch alias assignment and production-domain promotion are distinct. Git-source frontend candidate, automatic custom-domain assignment false, protected candidate qualification, one promotion and actual apex/www mappings establish the intended transition.

Carry native release authority by scope across routine deterministic corrections. A justified successor after a demonstrated defect is different from replaying an unknown write. Record source/service/reason and requalify changed dependencies; explicit one-operation limits and actual approval-review rejections still control. Do not use another agent/tool to bypass a rejection. Fully prepare one exact decision for any remaining confirmation; do not ask again for unchanged audio, rights, tone or acceptance evidence.

For unchanged media/player/lease/accounting dependencies, reuse genuine package-specific playback and settled accounting proof with its hashes/source bindings. Do not start a paid session under a no-paid-session instruction. A read-only public journey proves availability and denial behavior, not a new playback/accounting observation. Stop the completion monitor after verified public completion and retain final receipts/limitations.
